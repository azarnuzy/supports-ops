# Internal SOP: processing a Workspace deletion request

**Visibility: Internal-Only**

Workspace deletion is deliberately not self-service. When a Customer requests it through chat, do not confirm a timeline or promise deletion yourself — the AI Agent and first-line Human Agents record the request and escalate; only an Admin processes it.

Checklist before deletion is processed:

- Confirm the requester is an Admin on the Workspace, not just any user. Non-Admin deletion requests must be verified with the Workspace's actual Admin before proceeding.
- Check for an active subscription with the Business Tools. If one exists, cancellation and deletion happen together; do not delete a Workspace while leaving a subscription active, since it will continue billing.
- Record the stated reason for deletion in the Handoff. Product uses this for churn analysis even though it is never a condition for processing the request.
- Note the 30-day retention window to the Customer if they ask: data is recoverable during that period only, and only by contacting support again with the original request reference.

Never process a deletion based solely on an AI Agent's Escalation Summary without an Admin's own review of the conversation.
