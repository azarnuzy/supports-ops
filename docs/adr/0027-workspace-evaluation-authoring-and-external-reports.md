# Workspace evaluation authoring with external reports

SupportOps lets authorized Admins create and edit Workspace-owned Eval Datasets and manually start Eval Runs. The Testing page follows Quickchat's dataset list and creation drawer, with paste, selection from recent Sessions, and CSV inputs; it displays execution status and an external report link, while response review, scores, and comparisons remain in Anvia Lens or Langfuse. This keeps case curation close to Workspace configuration without building a second reporting product. Access follows existing Workspace membership and Organization Admin authorization (ADR-0026).

Eval Cases use the existing code-defined case shape: an ID, predefined input, expected answer, and metadata naming the category, metric, and metric-specific expectations. Inputs support a Customer Message, fixed history, clarification count, and extracted Attachment content. Each selected case executes once per Eval Run; there is no autonomous Customer simulator or repeated conversation loop. Admins can select a subset of cases. Dataset criteria provide defaults for judge-based metrics, while deterministic decision and required/forbidden Tool checks retain their existing semantics. Execution reuses Anvia SDK evaluation and the production AI Agent turn, evaluating the configured Workspace's Knowledge and assigned Tools as in ADR-0010. Live retrieval and read-only Tools are allowed; mutating Tools require a sandbox and are otherwise blocked, with that limitation visible in evaluation evidence.

Each Workspace owns one evaluation destination, managed by its Admins with backend, endpoint, encrypted server-side credentials, and dashboard URL. Evaluation traces and results go both to that destination and the platform's central Telemetry; the Workspace destination receives only its own evaluation evidence. The central destination remains in place for overall user tracing and marks evaluation traffic separately. A Workspace destination must not replace the process-global platform destination. Run requires configured credentials; temporarily retained undelivered evidence is retried without repeating model calls or charges, with execution and delivery status displayed separately.

Evaluated AI Turns spend Credits using the existing production eligibility and Model Rate rules (ADR-0021), from the Organization balance with Workspace attribution (ADR-0026). Judge calls also spend Credits, a deliberate extension of ADR-0021's per-AI-Turn billing boundary: a platform-defined Judge rate starts at one Credit per successful Judge model call. A metric requiring several Judge calls charges each successful call; deterministic evaluation does not itself make a Judge call. The Run confirmation shows estimated Credits before execution. Existing Unlimited Period behaviour remains applicable to Credit spending (ADR-0025 and ADR-0026).

Paste, message-only CSV, and selected Session Messages create draft cases for Admins to complete with expectations and metrics. Structured CSV also accepts complete case fields. Session selection may include preceding history; an existing AI Agent reply is not automatically a reference answer. Run uses complete selected cases only.

At Run creation, freeze the selected case contents and rubric and record the model and configuration identity used. Knowledge Sources and Business Tool data remain live; these snapshots do not promise an immutable external corpus or business-system state.

Each Run accepts at most 100 cases, with one active Run per Workspace. A case execution error is recorded separately from a failed evaluation score and does not stop unrelated cases. Model calls are not automatically repeated. Credit Exhaustion stops subsequent work and leaves remaining cases marked as not executed. Telemetry delivery retries reuse retained evidence without invoking models or charging again.

The user confirmed shared understanding of these design decisions. The three supplied Quickchat screenshots are execution references for the page and its creation source tabs. This ADR records the agreed design, not an implemented feature.

## Testing UX revision (2026-10-01)

The Admin confirmed inline response and grading review in SupportOps: the latest Eval Run appears above paginated Eval Cases, with errors and evaluator-health checks distinguished from pass/fail. This supersedes the external-only response-review boundary above; external backends still own detailed Telemetry and cross-run comparisons. New Eval Run Cases retain only the Customer-visible answer, decision, and metric scores/explanations locally; private reasoning is never stored. Older Runs do not gain answers retroactively.

Dataset creation selects Customer Messages directly, with server-side search, channel/date filters, pagination, and selections retained across pages. Imports include all valid rows within the existing source-size budget, rather than truncating at 100; 100 remains the per-Run limit. Large writes are batched within one transaction, so a failed batch leaves no partial import. XLSX templates provide dropdowns, guidance and reference sheets while CSV remains supported. Long message and history text is preserved, with expandable previews instead of the former 4,000-character limit; copied Session context is explicitly limited to the latest 20 earlier turns.
